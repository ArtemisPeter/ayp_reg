# The gate scanner uses a plain JS queue in local storage, not a service worker, and the native BarcodeDetector API

ADR 0002 committed to an offline-tolerant scanner; this records how that was actually built. The scanner page (`resources/views/gate/scanner.blade.php`) keeps the downloaded roster and any unsent scans in the browser's `localStorage`, and retries sending them on a timer and on the browser's `online` event — no service worker, no background sync API, no build step. We chose this over a full PWA/service-worker approach because the whole app is server-rendered Blade with no JS bundler in place (ADR-free convention already established: no `@vite` anywhere), and a plain queue is enough to survive a dead gate connection for the hours a camp runs; it does not survive the tab being closed before syncing, which a service worker's background sync could, but that trade-off was judged acceptable for the deadline.

**Superseded 2026-10-01:** QR reading originally used the browser's native `BarcodeDetector` API with no bundled library, falling back to manual name search where unsupported. In testing, this left the camera hidden far more often than expected — `BarcodeDetector` is not reliably available on desktop Chrome, not just Safari/iOS as anticipated. The scanner now always decodes frames locally with a self-hosted copy of `jsQR` (`public/js/jsqr.js`, downloaded directly rather than via an AI-mediated fetch, to guarantee byte-for-byte integrity of a library this security-critical), drawing the camera's video to a canvas and scanning it on every frame. This works identically across Chrome, Firefox, Safari and Android/iOS, and — being a self-hosted file rather than a CDN script — keeps working offline once the page has loaded once, preserving ADR 0002's offline requirement. The by-name search and "log by name" fallback remain for the genuine edge cases: no camera present, or the user declines camera permission.

A scan with no matching Attendee (QR unrecognized and not found by name) is still recorded, by typed name only, with no `attendee_id`, flagged for the Secretary to reconcile later — this is what makes ADR 0002's "let them in by name" promise concrete without inventing a placeholder Attendee record.
